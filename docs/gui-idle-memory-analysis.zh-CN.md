**GUI 空载内存分析 — 2026-10-25**

初始诊断：GUI 自然启动后的私有工作集为 **131.9 MiB**；强制回收 Go 垃圾和闲置页后为 **121.5 MiB**。Go 存活对象只有约 **16.5 MiB**，主要基础开销来自 Windows Vulkan／NVIDIA 驱动、交换链和图形管线。移除工作区预加载有可复现的收益；上传缓冲也存在空闲回收时机问题，但释放其容量不等于同量减少驻留 RAM。

随后按“文件对话框按需加载 → 3D 资源按需初始化 → 管线缓存加载顺序”修改了 Onix。五轮对照中，回收后 GUI 私有工作集均值从 **122.55 降至 111.18 MiB**；优化版存在首次测量偏高的情况，完整数据和限制见第 7 节。Pencode 原有未提交修改保留，前六节的候选方案没有因此全部实施。

**测量条件和口径**

- Windows amd64，Go 1.27.3，NVIDIA GeForce RTX 3060，Vulkan。
- Pencode 基于 `226f315` 加当前工作区已有修改；Onix 为 `4f1fa8c`。
- 默认启动器，无打开的项目、文件、终端；现有扩展照常加载。UI 使用 Microsoft YaHei UI，代码字体为 Consolas，字号 16；默认 Courier New 也会初始化。
- 项目窗口配置 1440×900，实际交换链为 1454×914；资源、主题、扩展使用当前用户配置。
- 所有数据均为 MiB，即 1 MiB = 1,048,576 字节。GUI、服务端和扩展是不同进程，本报告主表只算 GUI。
- Go 使用 `runtime.MemStats` 和堆采样；堆采样间隔 64 KiB，函数级数字是估计值。Windows 最终表使用外部 `QueryWorkingSet` 枚举实际工作集，配合 `VirtualQueryEx` 和 `GetMappedFileNameW` 分类。
- 原始探索数据中还保留了 `QueryWorkingSetEx` 结果；本机该接口枚举出的有效页比实际工作集约多 3.2 MiB，因此最终结论以 `final-*/natural-external.json` 和 `settled-external.json` 为准。
- “回收后”是在诊断构建中执行一次 `debug.FreeOSMemory()`，并在分析器退出采样后从外部再次取样。这是对照条件，不是建议在产品中频繁强制 GC。
- GPU 显存不等于进程工作集；以下 Vulkan 阶段增量包含驱动在 CPU 侧的堆、DLL 驻留及映射，不能直接当成纹理显存大小。

**1. 进程总量**

| 状态 | 总工作集 | 私有工作集 | 可共享驻留页 | 私有提交量 |
| --- | ---: | ---: | ---: | ---: |
| 自然启动后，无项目 | 207.52 | 131.88 | 75.60 | 261.40 |
| 一次 Go 回收、归还闲页后 | 198.11 | 121.54 | 76.54 | 250.75 |

私有工作集比较接近任务管理器常见的进程“内存”显示。总工作集还包含共享的程序、系统库和驱动页面，不能将多个进程的总工作集直接相加当作独占 RAM。提交量包含当前没有驻留物理内存的私有页，也不是任务管理器的驻留内存数字。两个 Windows API 分时取样，表中相加会有约 0.05 MiB 误差。

**3. Go 堆中是什么**

GC 后 `HeapAlloc` 为 **16.53 MiB**。不同次采样约为 16.3–16.6 MiB；一次自然启动快照为 17.07 MiB，也可能因最后一次 GC 的时机而更高。

以下分类来自一次回收后堆采样，按实际分配函数归类，合计约 14.8 MiB。采样值和 MemStats 精确总量存在误差，也不能用调用栈中的累计值再次相加。

| 分配来源 | 采样存活量 | 主要内容 |
| --- | ---: | --- |
| CSS 解析、编译、计算样式 | 约 5.04 | 其中 `styleIndex.commit` 约 2.8–3.0；其余为选择器、声明、属性预处理等 |
| 扩展及图标 | 约 2.59 | 其中所有主题的扩展图标缓存约 1.5–1.6，文件图标规则表约 0.6–0.7 |
| DOM、布局、HTML 组件 | 约 1.65 | 节点、模板克隆、属性和布局状态 |
| 客户端和通信协议 | 约 1.05 | `Client.read` 的响应缓冲是主要来源，约 0.83 |
| 字体解析和文字对象 | 约 0.98 | loca、hmtx、cmap 等解析表；不包括文件映射 |
| 图形、场景及绘制缓存 | 约 0.79 | Go 侧纹理更新、Canvas、场景快照等 |

比较明确的代码路径：

- `workbench/mod.go:Install`：启动器与预加载工作区各自安装一份视图、模板、CSS 状态。
- `workbench/highlight.go:loadSyntaxResources`：准备所有内置主题和对应 CSS。
- `workbench/extensions.go:cacheExtensionIcons`：为每个主题、每个扩展图标预生成多个前景色键值，即使尚未显示项目文件树。
- `workbench/fonts.go:initializeFonts`：在已选字体之外先载入默认字体；字体包装器和字体注册表已经跨视图共享。
- `../onix/html/style/intern.go:styleIndex.commit`：计算样式已经做了内容驻留去重，但单个 `ComputedStyle` 仍约 6 KiB。

空载没有活动文件，因此语法树、文档内容、撤销历史、大文件高亮、终端滚屏不是这里的大头。主程序链接了语法相关资源，也不代表全部语法已经解压到 Go 堆。

**5. Vulkan 的启动成本定位**

在同一原生渲染线程上记录初始化各阶段，得到以下增量。它们是当时的进程工作集变化，包含共享库首次载入、驱动编译和缓存；不是最终稳态组成，不能与上一节直接相加。

| 阶段 | 总工作集增量 | 私有提交增量 |
| --- | ---: | ---: |
| 窗口创建前 → Vulkan instance 初始化 | 约 24.4 | 约 15.7 |
| 创建设备 | 18.3 | 21.1 |
| 首次创建交换链 | 60.1 | 83.8 |
| 创建渲染通道、初始 framebuffer 表 | 约 0.03 | 约 0 |
| 管线资源和首个 sprite 管线 | 29.6 | 21.8 |
| 命令池、初始几何 | 约 0.6 | 约 0.01 |

从应用层看，创建窗口前工作集为 21.2 MiB，创建窗口后为 155.0 MiB，此时 Go 堆仅从 2.1 增加到 2.5 MiB。创建空窗口已经承担了大量原生图形成本。

另发现一次重复交换链创建：第一次和第二次都是 **1454×914**，只是圆角从 0 设置为 11。`onix_vk_set_corner_radius` 设置 `swapchain_dirty`，随后重新创建交换链；该交换链创建函数本身不读取圆角。第二次创建阶段工作集又增加约 27.2 MiB，但关闭这次重建的对照没有同量的稳态收益，只观察到很小且容易受驱动缓存影响的差异。因此应将它列为避免重复初始化／降低峰值的候选，而非承诺省 27 MiB 常驻内存。

**6. 已做的优化对照**

为了减少 Go GC 时机和采样自身分配的影响，最后一组对照先取自然启动数据，再采堆，最后单独执行一次回收，在外部测工作集：

| 变体 | 自然私有工作集 | 回收后私有工作集 | GC 后 Go 存活对象 |
| --- | ---: | ---: | ---: |
| 当前完整启动器，包含工作区预加载 | 131.88 | 121.54 | 16.53 |
| 只取消 `workspace.json` 预加载 | 121.88 | 114.83 | 11.57 |
| 只保留窗口及基础系统，无工作台模块 | 93.49 | 93.09 | 2.43 |

取消预加载在这组回收后对照中减少 **6.71 MiB 私有工作集、4.96 MiB Go 存活对象**；早一组对照减少约 5.6 MiB 私有页。可以将其理解为约 5–7 MiB 稳态收益，自然启动时还可能减少更多临时分配。代价是第一次进入工作区要进行原本提前完成的安装；需要验证首次打开项目的延迟。

另一组单进程上传缓冲对照：

| 状态 | 原生 staging 容量 | 私有提交量 | 私有驻留观测变化 |
| --- | ---: | ---: | --- |
| 启动后空闲 | 7.75 | 249.29 | 基线 |
| 请求 180 次渲染，让现有回收策略触发后 | 0.25 | 242.67 | 基本不变 |

缓冲容量下降 **7.50 MiB**，私有提交下降约 **6.62 MiB**；这次没有测到相应的驻留 RAM 下降。测试请求的是完整渲染循环，并非修改产品为持续渲染。

原因在 `../onix/render/native_buffer.h`：回收依赖 30 个低用量帧，且 Vulkan 有两个在途帧。Pencode 使用按需渲染，空闲时可能根本凑不够这些帧，启动上传高水位便一直保留。`CurrentBufferMemoryStatistics` 明确只统计部分缓冲，排除纹理、交换链和驱动分配；不能用其约 8 MiB 的数字解释全部原生内存。

**建议的优化顺序**

| 优先级 | 位置／方案 | 可期待的收益与约束 |
| --- | --- | --- |
| 高 | `main.go`：工作区改为第一次进入时安装，评估是否还需要启动预加载 | 已验证约 5–7 MiB 私有驻留；Go 存活对象约 5 MiB。进入后仍保留已热身的工作区，不必引入每次切换分配 |
| 高 | Onix：在 fence 安全后增加按空闲时间触发的一次缓冲维护 | 已验证 staging 可回收 7.5 MiB 容量；本机提交量减少约 6.6 MiB，RAM 收益不能保证。保持小容量热缓存和滞后策略，避免每帧或每次输入收缩 |
| 中 | `cacheExtensionIcons`：减少“所有主题 × 所有图标 × 所有前景色”的预展开 | 目前占约 1.5–1.6 MiB；可按实际使用的图标、主题组合缓存，已缓存热路径继续复用字符串。此数字是现存成本，不是已验证的全部可省量 |
| 中 | Onix HTML：共享可复用的不可变 CSS 编译结果，减少隐藏区域的首次构建；进一步压缩计算样式表示 | CSS 总成本约 5 MiB，其中计算样式约 3 MiB；注意已有样式去重，不能再把这部分当作完全重复。应优先处理重复状态和冷路径，避免用映射访问替换所有热路径字段 |
| 中低 | Onix：避免圆角设置触发同尺寸交换链重建 | 已确认重复创建；主要验证启动时间和峰值。没有证据支持几十 MiB 的稳态收益 |
| 低 | 通信接收缓冲使用有上限的闲置释放策略 | 当前约 0.8 MiB；要保留正常消息大小的热容量，避免频繁扩容 |
| 低 | 默认字体仅在所选字体失败／缺字时加载 | 当前字体映射实际驻留合计约 1.25 MiB，收益有限；解析表另计，需保护字体回退 |
| 架构评估 | 若目标远低于 100 MiB，比较 Windows 更轻的 GUI 图形后端／呈现路径 | 空窗口已约 93 MiB 私有驻留。继续只优化工作台 Go 对象，很难显著突破此基础成本；更换后端的收益尚未测量 |

这些候选收益存在重叠，不能直接相加。例如取消工作区预加载已经减少了部分 CSS、模板和样式内存；后续再压缩同一部分只能计算新增收益。也没有证据表明空载时存在持续增长的泄漏；本次主要定位固定启动成本和高水位保留，不代替长时间泄漏测试。

不建议把调低 `GOGC`、频繁调用 `FreeOSMemory`、裁剪 Windows 工作集当成主要优化。前者主要影响 Go 部分，后两者还可能以延迟和重新缺页换取较小的显示数字。裁剪二进制调试符号主要降低磁盘体积，不能按 exe 文件大小估算 RAM 收益。

**7. 已实施：按需加载和缓存顺序**

修改位于本地替换依赖 `D:/Workspace/onix`；Pencode 的生产启动代码没有新增诊断逻辑。

| 顺序 | 改动 | 首次使用和后续行为 |
| --- | --- | --- |

`shell32.dll` 仍由主窗口拖放功能使用，不能全部延迟到文件夹对话框。优化版启动时已经不加载 `comdlg32.dll`，但 `ole32.dll` 仍可能由其他系统组件／驱动加载。NVIDIA 图形 DLL 仍在进程中，不能将这次收益描述为卸载了显卡驱动库。

这些资源第一次使用后保留到窗口／驱动销毁。没有在关闭文件对话框或 3D 视图后立即卸载、反复重建，热路径仅检查初始化状态并复用已有资源。3D shader 模块和管线原本已按需编译，本次补上原先仍在启动时创建的布局、占位缓冲和采样器。

**重复测量结果**
