# 编辑快照数据流与分配优化

2026-10-30。接续前两阶段优化，处理原生编辑器中段输入时逐键生成全文字符串的问题。本轮同时修改 Pencode 和本地依赖 `../onix`，交付时需要保留两个仓库的改动。

## 数据流

```text
原生输入 → TextBuffer.ApplyEdits → 不可变 Snapshot
                                      ├─ 文件版本与保存基线
                                      ├─ TextField → Text2D → 行排版、选区、光标
                                      ├─ 撤销/重做的独立增量
                                      ├─ client.Document → 分块编码变更 → 后端
                                      ├─ 保存任务捕获版本 → 后台保存
                                      └─ LSP 同步任务 → 分块 JSON 编码 → 连接写线程
```

- Onix 新增 `piecetree.Snapshot`。原始字符串直接包装；首次编辑建立精确大小的索引 arena，之后用持久化 AVL 树共享未改文本，只建立受影响的路径。小叶块的合并复制有大小上限。
- `Snapshot` 可比较，版本标识用于 UI 和异步结果校验；需要判断文本是否相同时使用 `Equal`。`Chunks`、`ReadAt`、字节/rune/行定位不要求生成全文字符串。
- `String()` 是明确的全文请求，每个版本通过 `sync.Once` 最多生成一次，允许后台并发读取。`Materialized()` 用于回归测试确认输入、IME、保存和同步没有意外请求全文。
- 原生文档字段绑定 `Buffer`、`Source`，HTML 输入事件直接传递快照。普通短输入框和标签继续使用字符串；几何与 LSP 坐标接口通过泛型接受两种文本。
- `openFile`、保存任务、客户端同步状态、LSP 文档状态及编辑器版本缓存保存快照。保存时捕获的版本独立于后续输入，保存完成后按实际内容更新 dirty 状态。
- 语法高亮任务先传递快照，工作线程实际处理被选中的任务时才请求字符串。过时的排队版本无需提前生成全文。
- 原生替换输入一次提交删除与插入，避免发布中间删除版本。撤销历史仍只保存有字节预算的独立增量，避免截取字符串长期引用整份旧文档。
- 光标使用快照或缓冲索引定位，避免逐个 rune 重走树。选区扫描按相邻行累计，避免原始字符串反复扫描前缀。
- LSP 直接编码变更区间的文本块。全量同步按 JSON 转义后的大小预留编码缓冲，避免转义过程中把大消息缓冲翻倍；连接写线程完成使用后才能归还池。
- 查找缓存使用快照标识，选中查找结果和显示光标直接查询快照；空查询不生成全文字符串。

## 所有权与内存边界

快照节点、原始索引和已发布的字符串不放进 `sync.Pool`。UI、保存、LSP 和解析线程可以分别持有任意旧版本，编辑线程无法决定它们何时全部结束。池化可变节点会破坏不可变语义；在这里共享文本和交给 GC 回收更合适。

连接编码缓冲继续使用第二阶段的池：入队后由连接写线程独占，写入完成或关闭排空后归还，超过 1 MiB 不保留。全量同步仍然需要一个完整编码消息，不能声称零分配。

持续编辑仍会分配不可变路径节点、历史增量和部分 UI 状态。本轮消除普通中段输入帧中的全文复制，没有把整帧变为零分配，也没有把 B/op 当作 RSS 或 GC 后常驻堆。

## 当前仍会请求平面文本的消费者

- 后台语法解析和源代码 diff 的接口仍要求字符串。
- 非空查找/正则查询和替换仍使用平面字符串搜索接口；查找栏打开且有有效查询时，编辑后重算匹配仍可能生成全文。
- 原生输入会话初始化、切换焦点时的平台初始文本，以及部分扩展、工作区编辑和源码比较接口仍接收字符串。这些调用不属于本轮验证的持续输入帧。
- 缓冲保留内容超过回收阈值时，周期性压缩会重新建立连续内容，以释放已删除的大文本。

因此，“不生成全文”的回归覆盖普通文本编辑、IME 显示/提交、异步保存以及 LSP 分块同步；不应推广为所有编辑器功能永远没有全文分配。

## 基准

Linux amd64、i5-11500、Go 1.27.3。以下是每次操作的累计分配。最初保存的本轮基线临时目录已失效，不提供严格的修改前后比例或速度提升声明。

`BenchmarkNativeEditFrame` 从应用原始输入队列注入事件，在文档真正中点替换一个字符，运行完整工作台帧。预热 3 帧，计时 32 次，并断言最终版本未生成全文字符串。撤销历史和 UI 的分配包含在内。

| 文档目标大小 | B/op | allocs/op |
| --- | ---: | ---: |
| 64 KiB | 4,185 | 56 |
| 512 KiB | 5,572 | 72 |
| 2 MiB | 6,444 | 85 |

这些数据不包含首次建立文档索引，且仍随树高、历史和 UI 状态变化。分配量不再接近整个文档大小。时间受同时执行回归测试的负载影响，不作正式速度对照。

`BenchmarkSnapshotDocumentSync` 使用预先建立的两个分块版本，在中点交替修改，通过 `net.Pipe` 发送完整协议消息。预热 128 次并等待写入完成后计时 128 次；快照建立不计入该同步基准。它也断言没有调用全文物化。

| LSP 同步方式 | 文档目标大小 | B/op | allocs/op |
| --- | --- | ---: | ---: |
| 增量 | 64 KiB | 30 | 0（平均取整） |
| 增量 | 2 MiB | 0 | 0（平均取整） |
| 全量 | 64 KiB | 0 | 0（平均取整） |
| 全量 | 2 MiB | 2,450,022 | 3 |

低于一次的平均分配会被 Go 基准输出取整；池可能因 GC、并发队列增长和冷启动重新分配。2 MiB 全量同步超出池保留上限，每次分配编码消息。

```sh
go test ./workbench -run '^$' -bench '^BenchmarkNativeEditFrame$' -benchtime=32x -count=1
go test ./workbench -run '^$' -bench '^BenchmarkNativeTailEditFrame$' -benchtime=32x -count=1
go test ./lsp -run '^$' -bench '^BenchmarkSnapshotDocumentSync$' -benchtime=128x -count=1
```

## 验证

- 快照测试覆盖随机局部编辑、AVL 平衡与索引统计、跨块切片、UTF-8 边界（含无效字节）、CRLF 增量端点、历史版本不变、并发首次请求字符串和独立读取。
- 原生端到端测试覆盖中点输入与撤销/重做、保存阻塞期间继续输入、保存旧版本后 dirty 状态、IME 选区保留和提交、渲染几何，断言相关版本没有生成全文字符串。
- LSP 测试覆盖 UTF-8/16/32 坐标、CRLF、完整/增量同步、保存文本，以及 JSON 编码与标准库一致。
- Onix 的 `text/piecetree`、`input`、`scene`、`ui` 定向普通测试，以及根包、`ui/html`、`module` 测试通过。快照、输入、IME、光标与排版的定向竞态测试通过。
- Pencode 根包、`lsp`、`client`、`peb`、`textsearch`、`server/workspace`、`transport` 竞态测试通过。编辑、保存、历史、源码比较和自动补全的工作台定向竞态测试通过。
- 清理磁盘后，`go test ./workbench -timeout=240s` 的完整工作台回归通过，耗时约 82 秒。
- 引擎全包竞态命令中，原有 `TestTreeRandomEdits` 超过 120 秒超时；新增不可变快照测试已单独通过竞态检查。没有执行 `go test ./...`。
- 最终回归曾遇到磁盘不足导致编译和测试文件写入失败。清理超过三天未使用的可再生成 Go 缓存后，受影响的构建、客户端、工作区、自定义编辑器和设置测试复跑通过。

本轮未启动原生 GUI；视觉验收仍由手动操作完成。已有暂存和未暂存修改均保留，未提交代码。
