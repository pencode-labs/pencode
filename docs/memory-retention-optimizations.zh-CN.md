# 文档与终端内存回收优化

2026-10-29。本轮修改覆盖 Pencode 和本地替换依赖 `../onix`，需要一起保留。

后续正则搜索、扩展图标及工作区按需加载见[第二阶段记录](search-and-startup-memory-optimizations.zh-CN.md)；该阶段也已修复下文记录的模块加载接口不一致。

## 改动

- Onix `text/piecetree.Tree.Compact` 从树直接构造独立字符串，避免尾删后的短字符串继续引用旧的大块存储。已经发布给其他消费者的快照仍保持不可变。
- Onix `input.TextBuffer` 在压缩完成后发布新的快照，并释放超过 64 KiB 的粘贴／文本规范化临时缓冲。普通输入继续复用小缓冲和尾部快照容量。
- 客户端文档编码缓冲改为首次使用时分配，超过 64 KiB 的容量在请求处理后释放；服务端的 32 KiB 编辑区及节点预留延迟到首次修改。未编辑的标签页只保留正文、索引和工作线程等必要状态。
- 终端显式清空和 `CSI 3 J` 共用历史清理逻辑。超过 8192 个单元格的历史缓冲释放，小历史继续复用。没有改变历史行数、颜色、组合字符或普通屏幕擦除语义。

## 前后对照

Linux amd64，Go 1.27.3，每个场景、每个版本各启动三个独立进程。通过 Go overlay 仅替换本轮修改前的五个生产文件得到基线，其他代码及依赖相同。下表的堆增量在 GC 后测量；终端一项为仍被引用的底层切片容量，不是进程 RSS。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 32 MiB 文本尾删至 1 KiB，再压缩；仅保留树 | 32.000 MiB 堆增量 | 0.001 MiB |
| 粘贴 8 MiB，全选替换为 `small`，再输入 `!` | 8.062 MiB 堆增量 | 0.007–0.012 MiB |
| 120 列终端填满 2000 行历史，再清空 | 6.422 MiB 历史容量 | 0 |
| 200 列终端填满 2000 行历史，再清空 | 10.820 MiB 历史容量 | 0 |
| 打开 128 个未编辑的小文档，客户端＋内置服务端 | 10.822–10.824 MiB 堆增量 | 0.343 MiB |

文档场景通过生产协议和 `net.Pipe` 运行，不包含 GUI、LSP、扩展或原生窗口。实际工作台中，保存任务、撤销记录、已保存正文等仍可能合法持有旧文本，不能将这些数字直接当作整个应用的 RSS 降幅。大粘贴、首次编辑和清空后的重新积累允许按需分配；没有加入强制 GC 或定时回收产品逻辑。

- 新增回归覆盖尾删后独立存储、旧快照不变、输入改动范围、大粘贴清理、终端环形历史清空后继续写入，以及多个未编辑文档的总内存预算。
- 热身后尾部追加／删除、粘贴后的普通输入、服务端小编辑，以及小型终端历史的清空／重写仍通过零分配检查。
- 工作台定向测试无法编译：本地 Onix 的 `App.LoadModules` 已移除，而工作台两个测试文件仍调用它。这是本轮修改前已有的接口不一致，没有计为通过，也没有运行 GUI。

原始对照脚本、overlay 和日志位于 `/tmp/pencode-memory-opt.3p7qKf/`；临时目录可能被系统清理。回归测试保存在对应包中。
